# 日线自动更新与后续实时行情路线

2026-11-24已完成运行记录与采集提速升级，具体实现、真实联网对比和自检结果见[第1、2阶段验收记录](market-data-phase12.md)。生产并发暂保留2；新增股票历史补齐默认1并发。

第一阶段提供独立的日线更新链路，默认范围为项目已有的核心50股票池。完整是指这个明确股票池通过检查，不代表全A数据已更新。历史研究文件、旧回测结果和原策略准入不被新行情覆盖。

## 当前功能

- 按北京时间和真实交易日历确定最近完整交易日；16:30 前不把当天尚未完成的日线作为正式收盘数据。
- 默认18:30自动检查，服务启动后也会补查。安装了本机部署任务时，Windows任务计划程序会在周一至周五18:30运行，任务名为 `M-quant Daily Market Data`。
- 只重取没有通过当日检查的股票；每只股票的前复权历史整段替换，避免把不同复权基准的价格直接追加在一起。
- 东方财富、腾讯、新浪提供真实历史数据。备用数据源也必须返回目标交易日；不同来源的代码、日期、复权和成交量单位先统一再进入检查。
- 每次网络请求有超时、限速和有限重试；任务跨进程加锁，网页不会被采集任务同步阻塞。
- 检查OHLC关系、日期、成交量、最少240日历史和股票池覆盖率。任一股票未通过检查，不发布新快照或新观察信号，保留上次成功记录。
- 行情全部通过后，使用显式的新快照生成观察路线。自动产物全部是 `record_only`，不会修改原策略准入或创建订单。
- 网页顶部“每日行情更新”展示范围、数据日期、覆盖率和失败状态，并支持立即更新、查看本轮观察信号。

## 路径与入口

配置：`platform/quant-factor-platform/config/market-data.json`。

更新程序：`tools/market_data_refresh.py`。可使用已配置的Python环境运行：

```powershell
E:\M-quant\.venv\Scripts\python.exe tools/market_data_refresh.py
```

本地运行数据保存在 `outputs/live-market-data/`，已从Git跟踪中排除：

- `status.json`：最近任务、覆盖率和最近成功快照。
- `calendar.json`：数据源返回的交易日历及获取日期。
- `cache/`：每只股票通过校验的复权历史与来源元数据。
- `snapshots/<run_id>/`：不可变的当轮行情快照及观察信号。
- `runs/`：历次成功、失败或信号异常的任务记录。
- `worker.log`：后台任务输出。
- `requests/<run_id>.jsonl`：每次来源请求的耗时、结果与异常类型。
- `source-health.json`：来源健康度、冷却及恢复探测依据。
- `scheduler-status.json`、`scheduler-runs/`：系统任务独立回执，区分任务是否执行与行情是否完整。

接口：

```text
GET  /market-data-api/status
POST /market-data-api/refresh
GET  /market-data-api/signals
```

更新接口返回202后立即释放网页请求。信号接口会再次检查行情是否过期及是否为仅记录信号，不能用上次成功记录冒充新结果。

Windows部署脚本位于 `E:\M-quant\Run-Daily-MarketData.ps1`。任务使用当前用户登录态和普通权限；需要电脑开机且用户已登录，关闭网页不影响定时任务。不会让关机电脑自动采集数据，错过任务后可在恢复运行时补查。暂停或启用自动更新会同时影响任务计划程序和平台内调度。

自动失败重试为30分钟间隔、每时段最多3次。需要人工处理时网页保留缺口及原因，不能无限请求数据源。依赖免费公开数据源的可用性，不提供持续在线或指定延迟保证。

## 后续阶段

1. 日线阶段：先持续观察当前50只股票的成功率、补采次数和日期准确性，再扩到沪深300、中证500或明确的全市场股票池。新增股票、停牌和历史不足需要独立状态，不能伪造完整覆盖。
2. 分钟阶段：新增独立的分钟数据适配器、交易时段控制和闭合K线存储。只采集持仓和候选池，先做1—5分钟观察，不把尚未闭合的K线放进正式研究。
3. 近秒级阶段：选择有相应权限的数据源，优先使用行情订阅回调，再通过SSE/WebSocket推送到页面。行情快照与日线/分钟线分开存储，记录源事件时间、收到时间、心跳和断线补采。
4. 上线前验收：在真实交易时段测更新间隔和延迟分布；页面刷新速度不等于数据源速度。当前未验证任何账户的秒级行情权限，不能承诺实际延迟或费用。

分钟参考：[Tushare实时分钟接口](https://tushare.pro/document/2?doc_id=374)，其数据是已闭合分钟周期，需要单独权限。订阅参考：[XtData行情模块](https://dict.thinktrader.net/nativeApi/xtdata.html)，其通过MiniQMT连接并接收行情回调。数据源选择应以实际账户权限、适用范围、成本和实测延迟为准。
