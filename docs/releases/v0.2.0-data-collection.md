# v0.2.0 · 数据采集中心与行情图表

发布日期：2026-11-27，北京时间。此版本汇总本次数据采集层建设，并同步远端已有策略控制台/模拟观察平台更新。当前功能为真实行情采集、质量观察和研究支撑；未接入秒级订阅或自动下单。

## 已完成的功能

| 模块 | 本版行为 |
| --- | --- |
| 数据采集中心 | 独立入口；采集监控、行情图表、质量与记录、日线更新、股票数据管理库分开展示 |
| 日线更新 | 50股缓存、交易日历及日期/OHLC校验、完整通过后发布快照；计划更新和失败重试，观察信号仅记录 |
| 盘中采集 | 报价目标15秒、分钟目标60秒，独立进程与退避；报价、来源分钟OHLC和日线分别处理 |
| 来源诊断 | 逐股源时间、接收时间、内容变化、缓存与失败类型；有预算的定向恢复，保留历史失败 |
| 存储与补采 | SQLite及缓存一致性核对；独立补采队列，最新采集优先，候选与正式数据隔离 |
| 股票管理 | 管理库统一控制日线/报价/分钟/核查选择、优先级及版本；增删替换预览、冲突检查、恢复历史版本 |
| 历史准备 | 换股后分批准备日线、起点/覆盖校验、历史疑似缺口核查；交易时段让路 |
| 分钟证据 | 三只样本归档、跨轮标签/量价修订和关键边界观察；未确认闭合的分钟不进入正式策略 |
| 行情图表 | 涨跌分布、成交额排行、五档盘口、量额/时效摘要、报价与分钟耗时分图 |
| K线交互 | 日内1分钟OHLC不压缩；周/月各最多12根同源同口径日线聚合；放大缩小、平移、回最新、Ctrl滚轮 |
| 后台常驻 | 普通用户登录启动、独立守护、有限重启、持续手动停止、事件与滚动日志；网页关闭仍可运行 |
| 状态解释 | 周末主要显示下一交易日/时刻；收盘集合竞价边界待核实与已确认失败分开，历史任务可筛选 |
| 同步主线 | 保留最新内部策略控制台、策略搜索及统一Paper入口；外部导入入口沿用主线的关闭行为 |

基础平台、股票管理、图表、守护和分钟采集已具备；秒级核心数据接入尚未完成。不能把15秒轮询改成1秒就宣称取得真实秒级行情。

1. 核实可用数据源与账户权限、行情类别、原始更新时间和限额；从3只股票取得真实推送。当前公开轮询源不能据现有测试承诺一秒延迟。
2. 接入独立常驻订阅进程，记录来源事件/接收时间，处理乱序、重复、断线恢复和缺口；与历史补采分开。
3. 页面按事件推送，记录显示时间，验证“源时间→接收→显示”延迟，先3只再10/50只，真实盘中验收。

约需3—4批实施与盘中验证，具体日期取决于权限和实测。分钟闭合验证可并行进行；更高频报价不能代替可靠的正式分钟输入。若需交易所逐笔成交/委托，须另核实对应数据权限，不把报价快照称为逐笔。

## 运行与复检

本机已有部署：使用`E:\M-quant\Start-MQuant.ps1`和`Stop-MQuant.ps1`，本地页面`http://127.0.0.1:5555/#data-collection`。Windows部署参数在本机`deployment.json`，不上传到仓库。首次在其他电脑运行需配置Python环境、Node和本机部署路径；没有缓存时页面应显示缺失，不能自动拥有本机历史数据。

手工启动平台：先用Python 3.11+安装`requirements-market-data.txt`中的依赖；进入`platform/quant-factor-platform`，配置`PYTHON`为Python可执行文件，然后执行`node server.mjs`。此方式不自动安装登录守护。Windows守护安装脚本为`tools/windows/Install-MQuantService.ps1`；参考同目录`deployment.example.json`填写本机路径，将实际配置保存到所选部署目录的`deployment.json`，再把该目录作为DeploymentRoot传给安装脚本。

```powershell
python -m unittest discover -s tests
node --test platform/quant-factor-platform/tests/*.test.mjs
```

阶段记录见`docs/intraday-handoff.md`及各日期报告；原始自检文件位于本机忽略目录`outputs/live-market-data/`，上述测试命令与代码随版本保存。
