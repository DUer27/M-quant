# 股票数据管理库第一批

日期：2026-11-25，北京时间。已部署本地平台，未提交或推送；未启动或重置连续验收窗口。

## 使用入口

数据采集中心 →“股票数据管理库”。可按代码/名称搜索，查看已选采集和备用股票；分别选择日线、报价、分钟、核查及采集优先级，编辑股票名称或批量加入新股票。

新增股票默认只进入管理库、不自动采集。替换时关闭原股票相应开关，再勾选新股票；点击“预览变更”，核对受影响股票及前后数量，再“保存，下一轮生效”。每行“停止采集”只关闭该股数据开关，股票条目和历史数据仍保留。报价池最多50只，分钟须包含报价，核查最多3只且须采集分钟；目前支持沪深主板和创业板的00/30/60代码族，不自动接受ETF、北交所或B股。

“恢复此前股票池名单”会按历史版本生成新版本，不删除已有版本或行情。保存携带当前版本，另一个页面已保存时旧版本操作会拒绝，防止无意覆盖。

## 生效与保留规则

- 管理库config/stock-library.json是统一名单入口；日线名单和盘中代码由同一版本投影，旧名单文件保留。策略研究及账户交易逻辑未改变。
- Node控制器启动任务时保存不可变配置快照；已运行任务保持原股票池、数据类型与版本，下一轮读取新版本。相同配置复用相同快照，避免每分钟重复生成文件。Windows日线计划任务通过Python入口也会读取管理库。
- 每轮记录pool_id和pool_version；监控显示配置版本、最近/当前运行版本，以及是否等待下一轮生效。日线进行中展示该轮名单标签；新日线池尚未准备时旧快照保留并标为等待更新，不把旧快照当作新池完整结果。
- 新增股票页面明确显示日线待准备、报价待首次采集、分钟待首次采集或已有缓存。缓存存在不表示新鲜、完整或分钟闭合。
- 移出分钟池的补采任务改为paused_removed；重新加入时恢复原任务状态并重新核对日期/边界/额度，历史候选和主缓存不删除。本次万科A原边界任务已暂停。
- 分钟采集可以少于报价股票数，或全部关闭。覆盖率、图表提示及恢复时效判断使用对应数据类型的数量，不再固定写50只。旧验收窗口因股票池/版本变化提示失效，固定历史结果继续保留。

本批没有实现自动补全新增股票全部日线历史或扩容到50只以上；两只新增股日线缓存尚待下一次日线更新准备，可在日线页手动更新或等待既有18:30计划。期间新池显示等待状态是预期行为。
