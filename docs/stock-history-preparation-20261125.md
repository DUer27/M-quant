# 换股后的历史数据准备

2026-11-25，北京时间；已部署本地平台，代码未提交或推送。保留原连续验收窗口，本批没有启动新的统一连续验收。

## 页面与用法

数据采集中心 → 股票数据管理库 → “换股后的历史数据准备”。

保存名单后，后台自动检查已启用日线的股票。休市且最新行情、分钟补采、日线更新任务空闲时才执行历史准备；交易日09:25—15:05（含午休）不启动网络补历史。网页可以关闭，平台服务仍需运行。可点击“检查并准备历史”，或暂停/开启后续自动准备；暂停时当前一批可完成，草稿名单不会被提交。

面板显示已校验、待准备、失败及当前股票；每行显示历史条数、首末日期对应的状态、是否达到当前日线目标日期、失败原因与待核查缺口。编辑未保存名单时禁用手动准备，防止把草稿当作正式股票池。

## 执行与代价控制

- 固定当前股票池配置快照；运行中更改名单不改变已启动任务，页面按当前名单展示，下一批读取新版本。
- 与日线任务共用写锁，避免同时替换同股缓存。历史任务使用独立状态、日志和运行记录，不改日线发布状态、快照、观察信号或分钟行情。
- 先逐股校验已有历史，只下载缺失或未通过校验者；每批最多3只、单来源不立即重复尝试，沿用日线来源限速、失败切换和冷却。每批通常最多9次提供方尝试；不把这当作底层HTTP总数，第三方库可能内部发出多次请求。
- 成功但未完成的下一批至少间隔60秒；失败后至少等待30分钟，本版本每天最多3个自动失败批次。手动触发也限制至少60秒启动间隔。暂停开关独立保存为market-data.json的history_preparation_enabled。
- 检测到最新行情或日线任务启动、进入交易保护时段，或运行超过4分钟，会结束本工具创建的历史进程；Windows结束进程树，保留已落盘数据。中断后允许重新检查；失败保留旧缓存，不补零。
- 闲置时每15秒只读检查是否有待处理项目；全部准备完成后不会反复下载。缓存文件、元信息或校验要求变化会使旧回执失效，重新进入检查。

## 校验含义

复用既有OHLC、代码、日期、前复权口径和最少240条历史检查，并增加配置起点覆盖校验。来源虽然返回足够条数、却截断前段历史时，必须继续尝试其他来源，不能直接标为范围合格。缓存来源还须与元信息一致。新上市股票若没有配置起点之前的历史，会明确失败，需另行确认上市边界或调整所需历史范围，本批不会猜测上市日期。

“历史基础校验完成”不等于当日数据已更新，也不等于没有停牌/缺口。交易日内部没有记录的日期只显示“待核查”，没有证据时不推断停牌或来源漏数。日线更新仍单独校验目标日期及整个股票池后发布，原18:30安排保留。分钟闭合与近秒级行情不属于本批。
