# 10只样本交易时段自动采集与自检

实施日期：2026-11-24，北京时间。下一步选择先稳定现有10只，接入持续自动采集和异常反馈，再考虑20只扩样本。

## 已部署行为

- 自动采集已启用，平台服务保持运行时，在交易日09:30—11:30、13:00—15:00自动尝试采集。午休、非交易日、日历不足时暂停；仍支持手动采样。关闭网页不影响平台服务中的调度，关闭服务或关机则无法采集；未新增开机启动服务。
- 正常目标：以上一轮开始时间为基准，60秒启动下一轮，而不是每次完成后额外等60秒。至少留5秒调度余量。手动采集有30秒防重复间隔，自动采集按自身周期控制。
- 同时最多一个受管采集进程；在原进程退出得到确认前不会启动下一轮。Python跨进程文件锁继续保留。服务重启时若之前受管进程仍在运行，先等它退出，防止重复采集。
- 超过60秒：网页弹出提示，间隔临时调整至120秒；超过120秒调整至180秒；超过180秒请求结束进程树，在确认退出后冷却5分钟。网页提示不阻塞操作，可手动清除，同一事件不反复弹出。
- 恢复：连续两轮都满足10只完整报价、10只当前分钟数据、采集在60秒内完成，且全部源时间比上次合格轮推进，恢复60秒间隔。重复返回、旧数据、缓存、部分覆盖不算恢复。
- 报价新鲜阈值90秒；分钟接口源时间阈值180秒。两种阈值分别显示，不代表分钟K线闭合语义已验证。恢复检查要求一路报价完整覆盖，不把不同报价来源凑成完整源。
- 收盘/午休后完成的采样标记为休市观察，不用它认定实时达标，也不计入恢复。仍未接账户或下单通道，分钟闭合规则继续标记待验证。
- 同一数据源的报价与分钟接口分别记录健康度；连续失败或403/429进入冷却，支持Retry-After的秒数或HTTP日期。个别来源冷却不会阻塞健康备用来源；相关类型的所有来源都冷却时，整体调度遵守等待时间。
- 新增报价缓存，分钟缓存继续保留。失败或源时间倒退时保留较新的成功数据并标记“上次成功”，不计入本轮覆盖率或恢复判断。
- 自动轮只保留精简历史报告，完整分钟序列写入当前状态和股票缓存；不逐轮重复保存全部原始响应。手动试验仍留原始响应。运行历史保留最近120轮状态，页面展示最近20轮与耗时柱图、60秒目标线。

## 使用

打开 http://127.0.0.1:5555/#intraday-trial-panel ，查看“盘中关键数据 · 10只样本”：

- “暂停自动更新”/“启用自动更新”按钮持久保存开关，暂停后当前轮可结束。
- 显示当前周期、下一轮或等待交易时段、超时弹出提示。
- 展开“自动降频、恢复与暂停记录”和“最近20轮采集验收记录”，查看自动决策依据。
- 五秒读取一次页面状态，仅刷新展示，不会额外触发数据源请求。

## 文件与边界

- 配置：`platform/quant-factor-platform/config/intraday-trial.json`。
- 调度逻辑：`platform/quant-factor-platform/intraday-policy.mjs`、`intraday-trial.mjs`。
