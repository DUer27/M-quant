# JoinQuant 策略实测与交叉回测要求

## 目标

本文件定义 M-quant 策略从候选信号到模拟观察前必须完成的 JoinQuant 回测要求。

核心原则：策略实测只认 JoinQuant 实跑或研究环境真实计算结果。本地 AkShare 结果可以作为候选证据，但不能直接等同正式策略回测。

## 数据边界

- 行情数据必须来自 JoinQuant 真实接口，例如 `get_price`。
- 基本面、市值、换手和成交状态必须来自 JoinQuant 真实接口，例如 `get_fundamentals`、`valuation.market_cap`、`valuation.turnover_ratio`。
- 资金流相关策略必须使用 JoinQuant 可得真实字段，例如 `get_money_flow`。
- 不允许手填收益、补造缺失字段、用展示数据代替真实回测。
- 未导入真实 JoinQuant JSON 前，只能说明策略可复核，不能说明策略有效。

## 回测层级

策略需要分三层验证，不能只看单一收益表。

1. 事件收益检验：验证信号后未来收益是否有方向性。
2. 分层与交叉分层检验：验证策略只在哪些市场状态、市值层或流动性层有效。
3. 完整交易回测：加入调仓、持仓、成本、滑点、停牌、涨跌停和容量约束。

事件收益结果好，只能说明信号值得继续研究；完整交易回测通过，才可以进入模拟观察或策略成熟度审计。

## 基础周期

每个策略至少输出以下持有周期结果：

| 周期 | 用途 |
| --- | --- |
| 1日 | 检查次日有效性、追高风险和短期反转。 |
| 5日 | 当前主交易周期，用于调仓净值、胜率、回撤和成本压力评估。 |
| 10日 | 检查中短期延续性，避免只在 5 日窗口偶然有效。 |
| 20日 | 检查月度级别延续性，适合趋势、防守和低波动策略。 |

当前系统已有较多 `5/10/20日` 结果。后续 JoinQuant 脚本应补齐 `1日`，形成统一的 `1/5/10/20日` 矩阵。

## 事件收益输出字段

每个策略、每个周期、每个分层组合至少输出：

| 字段 | 含义 |
| --- | --- |
| `source` | 结果来源，例如 `joinquant_xxx`。 |
| `result_type` | 结果类型，例如 `strategy_backtest`、`strategy_regime_size_backtest`。 |
| `strategy_id` | 策略机器名。 |
| `strategy_name` | 策略展示名。 |
| `horizon` | 持有周期，要求覆盖 `1/5/10/20`。 |
| `sample_dates` | 有效测试日期数。 |
| `sample_trades` | 股票样本数。 |
| `mean_return` | 单股票平均收益。 |
| `median_return` | 单股票中位收益。 |
| `positive_ratio` | 单股票正收益占比。 |
| `daily_mean_return` | 按日等权组合平均收益。 |
| `daily_positive_ratio` | 按日组合正收益占比。 |
| `best_daily_return` | 最好单日组合收益。 |
| `worst_daily_return` | 最差单日组合收益。 |
| `avg_candidates_per_date` | 平均每日候选数量。 |
| `data_policy` | 数据真实性说明。 |
| `note` | 结果边界说明。 |

## 交叉回测矩阵

每个正式候选策略必须做交叉分层，不只看全样本平均结果。

最低要求：

```text
3个市场波动层 × 3个市值层 × 4个周期 = 36条事件收益结果
```

其中：

- 市场波动层：高波动 / 中波动 / 低波动。
- 市值层：大市值 / 中市值 / 小市值。
- 周期：1日 / 5日 / 10日 / 20日。

如果策略依赖交易可行性，还应增加流动性分层：

- 高流动性 / 中流动性 / 低流动性。
- 使用 JoinQuant 真实成交额、换手率或 `money_ma20`。
- 低流动性样本即使收益好，也不能直接进入模拟观察。

## 市场状态定义

市场状态沿用当前 M-quant 口径：

- 指数：沪深300 `000300.XSHG`。
- 指标：20 日滚动年化波动率。
- 高波动：历史滚动分位 `>= 70%`。
- 低波动：历史滚动分位 `<= 30%`。
- 中波动：介于高波动和低波动之间。
- 分位计算必须只使用历史可见数据，建议使用 `shift(1)` 避免未来函数。

## 市值分层定义

市值分层使用 JoinQuant `valuation.market_cap` 当日截面分位：

- 大市值：`market_cap_rank_pct >= 0.67`。
- 小市值：`market_cap_rank_pct <= 0.33`。
- 中市值：介于两者之间。

每条交叉分层结果必须同时带上 `market_regime` 和 `market_cap_bucket`。

推荐枚举值：

```text
market_regime: high_volatility / medium_volatility / low_volatility
market_cap_bucket: large_cap / mid_cap / small_cap
```

## 完整交易回测要求

进入正式候选或模拟观察前，每个策略必须额外完成交易型回测。

最低要求：

- 默认调仓频率：5日调仓。
- 可选对照：1日、10日、20日调仓。
- 买入规则：按策略得分排序，TopN 等权或按既定风险权重。
- 卖出规则：到期调仓、信号消失、无法交易处理。
- 成本：佣金、印花税、滑点、冲击成本。
- 成本压力：至少基础成本和压力成本两档。
- 交易约束：停牌、涨跌停、一字板、无成交、价格异常必须处理。
- 容量约束：平均可交易候选数量、单票成交额、换手率必须检查。

交易回测输出字段至少包括：

| 字段 | 含义 |
| --- | --- |
| `result_type` | `strategy_trading_backtest` 或 `trading_backtest`。 |
| `strategy_return` | 策略累计收益。 |
| `annual_return` | 策略年化收益。 |
| `benchmark_return` | 基准累计收益。 |
| `excess_return` | 超额收益。 |
| `max_drawdown` | 最大回撤。 |
| `sharpe` | Sharpe。 |
| `daily_win_rate` | 日度或调仓期胜率。 |
| `avg_turnover` | 平均换手。 |
| `trade_count` | 交易或调仓次数。 |
| `date_range` | 回测日期范围。 |
| `data_policy` | 数据真实性说明。 |

## 股票池与过滤

每次回测必须明确股票池和过滤规则。

必填范围：

- 股票池：沪深300 / 中证500 / 全A / 自定义股票池。
- 基准：与股票池匹配的指数或等权基准。
- 复权：明确前复权、后复权或不复权口径。
- 剔除：ST、退市整理、上市时间过短、停牌、无法交易标的。
- 涨跌停：买入日涨停、卖出日跌停不能假设成交。

## 样本量门槛

事件收益最低门槛：

- 单个分层 `sample_dates >= 20`。
- 平均每日候选数 `avg_candidates_per_date >= 10`。
- `sample_trades` 不能由极少数日期或极少数股票贡献。

交易回测建议门槛：

- 调仓期数 `trade_count >= 60` 更稳。
- 年度分段不能只靠单一年份贡献收益。
- 最近一年或最近若干期不能明显失效。

样本量不足时，结果只能标记为观察或待复核，不能升级为成熟策略。

## 通过标准

事件收益层建议标准：

- 主周期 `daily_mean_return > 0`。
- 主周期 `daily_positive_ratio >= 0.55` 更适合继续。
- `daily_positive_ratio` 在 `0.50` 到 `0.55` 之间只能观察。
- 1/5/10/20 日不能只靠单一周期极端好看；主周期和相邻周期应方向一致。
- 至少一个清晰分层稳定有效，不能只看全样本平均。

交易回测层建议标准：

- 策略收益为正。
- 超额收益为正。
- 最大回撤可接受。
- Sharpe 至少大于 1 更适合继续。
- 成本压力后仍不失效。
- 候选数量和成交容量满足交易要求。

通过结果只能开放对应分层。若只有 `低波动/大市值` 通过，只允许该路线进入候选或模拟观察，不能放开整策略。

## 样本外与滚动检查

每个正式策略必须拆分检查：

- 样本内：参数形成阶段。
- 样本外：参数冻结后的验证阶段。
- 年度分段：逐年收益、回撤、胜率。
- 滚动窗口：每 6 个月或 12 个月滚动复核。
- 最新信号复核：最近交易日是否仍满足策略准入条件。

最近信号复核不生成未来收益，只检查候选容量、交易状态、市值层、市场状态和可交易性。

## 多策略交叉检查

多个策略准备同时进入模拟观察时，必须做资金袖独立性检查。

至少检查：

- 持仓重叠率。
- 信号日期重叠率。
- 市场状态重叠。
- 市值层或流动性层重叠。
- 因子来源和策略组件重叠。
- 高波动/低波动是否互斥。
- 是否只是同一策略组件换名或重包装。

如果两个策略共享核心组件，只能一个作为主资金袖，另一个作为组件监控或备选。不能把高度重叠的两条路线重复计算为两条独立成熟策略。

## 推荐执行顺序

```text
1. JoinQuant 拉取真实 OHLCV、基本面、市值、换手和交易状态。
2. 生成策略信号和候选池。
3. 输出全样本 1/5/10/20 日事件收益。
4. 输出高/中/低波动 1/5/10/20 日事件收益。
5. 输出大/中/小市值 1/5/10/20 日事件收益。
6. 输出高/中/低波动 × 大/中/小市值 × 1/5/10/20 日交叉结果。
7. 对有效分层做 5 日调仓交易回测。
8. 做基础成本和压力成本回测。
9. 做年度分段、样本外、滚动窗口和最近信号复核。
10. 做多策略持仓、日期、组件和资金袖独立性检查。
11. 将真实 JSON 回填 M-quant 回测中心。
12. 通过成熟度审计后，才允许进入模拟观察。
```

## 最终判定口径

- `待复核`：只有本地 AkShare 或草案结果，未导入 JoinQuant 真实结果。
- `可继续`：JoinQuant 事件收益为正，样本和分层初步达标，但未完成交易回测。
- `观察`：部分周期或部分分层有效，仍需补样本、成本或交易可行性。
- `偏弱`：收益、胜率或样本稳定性不足。
- `交易通过`：完整交易回测收益、超额、回撤、Sharpe、容量和成本压力均达标。
- `可进入模拟观察`：交易通过，并完成最新信号复核与多策略独立性检查。

简化总结：先用 JoinQuant 做 `1/5/10/20日` 事件收益矩阵，再做 `高/中/低波动 × 大/中/小市值` 交叉回测，最后用含成本、滑点、停牌涨跌停规则的 5 日调仓交易回测决定能不能进入模拟观察。
