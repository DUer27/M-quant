# 报价与分钟独立采集：第一批

2026-11-25，北京时间。已部署本地平台，代码未提交或推送。股票池仍为管理库v2，报价50只、分钟50只；未启动新的统一连续验收。

## 当前行为与入口

数据采集中心 → 采集监控。新增“报价与盘口”“分钟K线样本”两张卡片，以及“只更新报价”“只更新分钟”按钮。原“手动采集一次”同时启动两类；其中一类已经运行时，另一类仍可独立启动。

交易时段自动更新目标为报价15秒、分钟60秒；网页每5秒拉取状态，倒计时/源时间差每秒刷新。目标是调度频率，不保证供应商同频率推进，不等于行情源到页面的延迟。后台发布后，页面轮询仍可能增加约0—5秒等待；本批没有做订阅推送。

每类显示自己的覆盖数、时效合格数、采集耗时、来源时间范围、最近接收时间、页面同步时间、配置版本和下一次安排。旧缓存保留自己的接收时间；报价新不代表分钟新。新任务尚未产生报告时不会把上一轮运行编号和指标当作新任务结果。

## 调度、隔离与失败处理

- 报价在quote-lane独立进程、运行锁、报价缓存、来源状态、诊断和SQLite存储运行。分钟继续使用现有主分钟缓存、分钟SQLite、核查与补采队列。两个数据库各自写入，避免并发更新共享状态文件。
- 采集器增加--lane quote/minute；报价模式不请求分钟、不创建分钟补采任务，分钟模式不请求报价。默认combined模式为旧流程保留。
- 报价第一个来源返回后即发布其检查结果，后续来源和分钟不用完成才能显示。每个任务使用不可变股票池快照；新名单在后续任务生效，旧版本报告不计当前版本的新鲜覆盖。
- 每类同一时刻最多一个进程。超过自身更新目标会独立延长间隔并提示；报价45秒、分钟180秒硬终止对应进程树，分别冷却至最长120/300秒。当前恢复规则为连续两轮完整、来源时间推进、且在自身目标内完成后恢复该类型目标频率。
- 来源退避按类型隔离。分钟失败或冷却不会延长报价间隔；某一个报价来源故障也不会阻止健康报价来源。失败保留成功缓存和失败记录，暂停自动更新允许已经开始的任务完成。
- 历史补采和数据准备继续让路给最新任务。分钟补采与分钟主采集仍共用原运行锁。服务重启保留活动进程归属，确认退出前不叠加同类型进程。
- 调度状态仅在启动、完成、退避等状态变化时落盘，不每秒重写全部历史。报价自动运行的归档去掉重复诊断明细，当前诊断保留在最新状态。

## 代价与后续

报价常规请求由每分钟约2次提升到约8次，分钟正常路径仍约50次；来源切换与定向复查会增加请求。报价定向复查每轮最多1次、8秒启动预算，分钟保留原独立预算，二者不可借用。免费通道容量和稳定性仍需实际盘中记录确认。

两个进程同时运行会增加内存峰值，报价快照与运行记录也会增加磁盘占用。本批通过单类型不重叠、独立退避、轻量自动归档、配置快照复用与减少闲置写盘控制代价；尚未提供长期数据保留/清理策略，后续应按实际增长量安排。

下一批优先推进小样本分钟标签、形成中/已闭合状态与数据使用规则；策略取数准入、订阅数据源、长时间稳定性与统一验收按后续批次推进。本批未把未验证分钟样本开放给正式策略。
