# 逐股停滞诊断与定向恢复

日期：2026-11-25。本批只完成逐股诊断和定向恢复，统一连续验收按用户要求推迟。没有新建或重置验收窗口，也未修改此前固定窗口未通过的结论。

## 页面入口

打开 http://127.0.0.1:5555/#data-collection →“质量与记录”→“逐股更新诊断与定向恢复”。默认显示需关注项和复查记录，可切换“全部观测”查看50只股票的两路报价和一路选用分钟数据，共150项初次观测。

每项记录包含股票、来源、数据类型、初次/复查阶段、前次/本次源时间、各自接收时间、内容版本、最近一条价格/数量字段、变化字段、源标签时间差和是否需要复查。历史基线不足时明确显示未知，不根据之前未保存的信息补造原因。

能区分：源时间推进；标签未变但内容修订；标签与内容均未变；源时间倒退；接收顺序倒退；网络、字段校验、本地保存失败；来源冷却或预算跳过。标签和内容相同只作为缓存或无新成交等情况的核查线索，不直接认定原因；内容修订不意味着分钟已闭合。

## 定向恢复规则

- 先完成正常股票池采集，再只处理本轮发现的停滞、时间倒退或明显滞后目标；正常股票不重复抓取。
- 默认每轮最多3个股票/类型目标、额外最多4次真实外部请求；同一目标实际复查后冷却180秒。报价复查按同一来源批量请求所选股票，分钟仅请求对应股票。
- 复用原有请求会话、来源限速及故障冷却，不另开一套并发额度。来源冷却、请求数或时间预算不足会记录跳过原因。
- 正常采集完成后，对刚收到的待复查目标至少留2秒观察间隔；优先同源复查，必要时分钟尝试备用来源。原解析、时效和未来边界隔离规则继续执行。
- 从本轮采集开始50秒后不再启动额外请求；复查连接/读取超时分别为2/3秒。网络和系统调度仍可能拖延，50秒是启动预算，不是承诺整个任务硬性在50秒结束。
- 分钟只有在新标签更晚、时间差≤180秒且成功保存后，才标为恢复并选用整段新序列。切源保留来源信息，不拼接两来源K线；没有更新标签的复查响应保留诊断和原成功数据。
- 报价复查只更新同源对应股票，保留每股真实接收时间；只有源时间推进并满足≤90秒时效才标为恢复。
- 初次与复查响应均保留。监控、图表、覆盖率和时效判断统一使用被选中的分钟序列，避免后台更新而页面仍指向初次响应。
- 休市、午休不额外复查。收盘后源时间差只作记录，不作为盘中稳定性结论。

配置位于platform/quant-factor-platform/config/intraday-trial.json的targeted_recovery。状态文件symbol-diagnostics-state.json保存来源隔离的诊断基线；symbol-recovery-state.json保存逐目标冷却；symbol-diagnostics.json保存本轮过程。记录随本地运行报告保存。可选状态损坏会提示，恢复状态不可信时停止额外复查，正常成功样本继续保留。
