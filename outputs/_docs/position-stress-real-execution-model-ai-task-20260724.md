# 压力测试模型升级执行方案：成交上限、部分成交、卖出滞留、资金阶梯扫描

生成时间：2026-07-24  
适用项目：M-quant  
目标模块：压力测试板块  
核心目标：把当前“资金放大但交易路径不变”的压力测试，升级为“成交约束会改变买卖、持仓、收益、回撤”的真实成交压力测试。

## 一、给执行 AI 的总任务

请在当前仓库中实现一版新的压力测试模型，优先加入以下四个能力：

1. 单票单日成交上限。
2. 部分成交。
3. 卖出滞留。
4. 资金阶梯扫描。

这版先不要做复杂盘口冲击成本，也不要做分钟级模型。目标是用最少假设，把“资金变大以后买不满、卖不完、持仓路径改变、收益回撤随之改变”真实反映出来。

## 二、当前问题

现有压力测试脚本主要位置：

- `outputs/position-stress/scripts/position_stress_lab.py`

当前动态持仓账本能处理：

- 手数取整。
- 固定佣金。
- 固定滑点。
- 印花税。
- 现金缓冲。
- 止盈、止损、趋势健康退出。

但它没有处理：

- 单票单日最多能成交多少钱。
- 目标买入金额超过成交上限时只能部分买入。
- 目标卖出金额超过成交上限时只能部分卖出。
- 未卖出的仓位继续留在组合里承受后续波动。
- 因部分成交导致真实持仓天数、成交笔数、收益、回撤发生变化。

因此当前高金额回放仍然显示较高收益率，这不是可靠的大资金容量结果。

## 四、核心规则

### 1. 成交上限

每只股票每天最多成交当天真实成交额的一定比例。

默认参数：

```text
--max-participation-pct 0.05
```

含义：单票单日最多成交当天成交额的 5%。

同时支持：

```text
0.03、0.05、0.10
```

用于做不同红线的压力扫描。

成交额来源：

- 优先使用行情表中的真实成交额字段 `amount`。
- 如果 `amount` 缺失，但 `close` 和 `volume` 存在，可用 `close * volume * 100` 做兜底近似，因为本项目缓存中的成交量以“手”为单位。
- 如果成交额仍不可得，该股票当天视为不可做容量约束成交，建议默认不允许新买入，卖出侧可进入“无法估算成交额滞留”状态，并在报告里标红。

### 2. 买入部分成交

当目标买入金额大于当日可成交金额时：

```text
实际买入金额 = min(目标买入金额, 当日可成交金额, 可用现金)
```

实际股数仍需按 100 股一手取整。

未买成的金额不应该凭空成交，应保留为现金。

买入不足后，组合仓位可以低于目标仓位。

报告需要记录：

- 目标买入金额。
- 实际买入金额。
- 未成交买入金额。
- 买入成交比例。
- 是否因为成交上限导致买入不足。

### 3. 卖出滞留

当目标卖出金额大于当日可成交金额时：

```text
实际卖出金额 = min(目标卖出金额, 当日可成交金额)
```

实际卖出股数按 100 股一手取整。

未卖完的股票必须继续留在持仓里，不允许按理想价格直接清仓。

未卖部分继续承担之后每天的真实价格波动。

报告需要记录：

- 目标卖出金额。
- 实际卖出金额。
- 未卖出金额。
- 未卖出股数。
- 卖出成交比例。
- 滞留天数。
- 滞留期间最大亏损。
- 最终是否全部卖完。

### 4. 卖出优先级

卖出比买入更重要。

每天处理顺序建议为：

1. 先计算已有持仓的退出信号。
2. 对触发退出的持仓执行卖出，但受成交上限限制。
3. 未卖完部分继续保留。
4. 卖出释放的现金，加上原有现金，再处理新买入。
5. 新买入同样受成交上限限制。
6. 收盘后按真实收盘价重估组合市值。

不要先买后卖，否则会低估卖出流动性风险。

### 5. 同一股票同一天买卖占用成交上限

如果同一只股票同一天既有卖出又有买入，应共享同一个成交上限。

建议规则：

- 先卖出，占用当天该股票成交容量。
- 买入只能使用剩余成交容量。

这样更保守，也更符合风险管理。

### 6. 资金阶梯扫描

新增一个资金阶梯扫描功能，建议参数：

```text
--capital-sweep 1000000,10000000,20000000,30000000,40000000,50000000,80000000,100000000
```

对每个资金规模都完整重跑真实成交约束账本。

不能只线性外推，因为部分成交和卖出滞留会改变路径。

资金阶梯输出至少包括：

- 初始资金。
- 总收益率。
- 年化收益。
- 最大回撤。
- 成交笔数。
- 平均持仓天数。
- 平均仓位。
- 目标买入金额。
- 实际买入金额。
- 未成交买入金额。
- 目标卖出金额。
- 实际卖出金额。
- 未卖出金额。
- 最大单票参与率。
- 平均参与率。
- 95 分位参与率。
- 最大滞留金额。
- 最大滞留天数。
- 因成交上限造成的收益损失。

## 七、关键验收标准

### 1. 资金变大后结果必须变化

在真实成交约束模式下，随着资金规模提高，下列指标应该可能发生变化：

- 总收益率。
- 最大回撤。
- 平均持仓天数。
- 成交笔数。
- 平均仓位。
- 未成交金额。
- 卖出滞留金额。

如果这些指标仍然几乎完全一样，说明成交约束没有真正进入路径。

### 2. 不能凭空成交

任何一天任何股票的实际成交金额都不能超过：

```text
当天成交额 × 单票成交参与率上限
```

同一股票同一天买入和卖出合计也不能超过这个上限。

### 3. 卖出失败必须继续持仓

如果卖出受限，未卖出的股票必须继续出现在持仓里，并继续按后续价格波动计入组合净值。

不能在报告里显示已经全部退出。

### 4. 买入不足必须保留现金

如果买入受限，未买成的金额必须留在现金中，不能自动补成目标仓位。

### 5. 资金阶梯必须完整重跑

每个资金规模必须重新运行完整组合账本，不能用 100 万结果线性外推。

### 6. 中文报告必须说明模型假设

报告中必须明确写出：

- 单日成交上限是多少。
- 成交额缺失时怎么处理。
- 买入不足怎么处理。
- 卖出滞留怎么处理。
- 为什么结果比旧模型更可信。
- 哪些部分仍然是假设。

## 九、预期结果形态

完成后，报告不应该再出现“1 亿、2 亿收益率几乎不变，因此看起来也能承受”的误导。

预期结果应该类似：

- 100 万和 1000 万基本接近旧模型。
- 3000 万附近开始出现买入不足或轻微卖出滞留。
- 5000 万以上收益率、回撤、持仓天数开始明显偏离旧模型。
- 1 亿以上出现明显未成交金额、卖出滞留和容量损失。

具体数字以真实重跑为准，不要预设结论。
