# 独立模拟盘实施计划

## 目标与边界

- 在当前 `M-quant` 同级创建独立 Git 仓库：`../mquant-execution`。
- `M-quant` 只负责研究、策略状态和导出版本化信号；不 import 模拟盘代码、不接触模拟盘数据库。
- `mquant-execution` 负责信号导入、SQLite 数据库、资金流、目标持仓再平衡、订单/成交模拟、T+1、费用滑点、快照、对账和只读监控页面。
- 第一版只允许 `PAPER` 模式，明确拒绝 `LIVE`；默认绑定 `127.0.0.1`，不保存任何券商 API Key。
- 运行时数据库和行情文件放在 `runtime/`，不进入 Git；仓库提供迁移、备份、恢复和 JSON/CSV 导出。

## 现有代码利用方式

- 迁移并重构 M-quant 当前 `execution/a_share_paper/` 中已经验证过的信号校验、幂等、A 股交易规则、风控、费用和滑点测试思路。
- 不直接沿用现有的 `state.json` 作为生产账本：改为 SQLite 事务、追加式资金账簿和可重建的持仓快照。
- M-quant 中删除/替换旧的 `execution/a_share_paper/` 子项目，避免模拟盘继续作为 M-quant 子项目存在；保留新信号合同文档和导出适配代码。`execution/rqalpha_backtest_view/` 不受影响。

规则：

- `signal_id` 对相同策略、信号日、袖、目标组合做确定性哈希，保证重复下载/导入不重复交易。

- 当前平台只有 `selected_codes` 时，按 `planned_weight / selected_count` 等权生成目标组合；剩余部分保留现金。
- 控制器、阻断策略或未通过准入的策略导出为 `RECORD_ONLY`，不允许模拟盘产生订单。
- 不把未来收益、回测收益或未验证业绩写入可交易信号。

### 数据库与一致性

使用 Python 标准库 `sqlite3`，默认开启：

- `PRAGMA foreign_keys=ON`
- `journal_mode=WAL`
- `synchronous=FULL`
- `busy_timeout`
- 每次信号执行、成交结算、人工资金流均使用事务。

初始迁移建立以下表和约束：

- `schema_migrations`：迁移版本。
- `accounts`：账户、币种、初始资金、状态、配置快照。
- `account_balances`：可用现金、冻结现金、可提现现金、总资产等物化余额。
- `cash_ledger`：追加式资金账簿，记录入金、出金、买入扣款、卖出结算、手续费、调整和结算释放；使用唯一幂等键防止重复记账。
- `signals`：完整原始信号 JSON、哈希、策略版本、状态、导入时间和执行时间。
- `signal_positions`：信号中的目标标的、权重、目标数量、排名。
- `quotes`：行情快照的时间、价格、买一/卖一、成交量、可交易状态、停牌和涨跌停字段。
- `orders`：订单请求、目标来源、方向、数量、价格、状态、风控原因和幂等键。
- `fills`：成交明细、成交价、成交量、手续费、滑点、成交时间。
- `position_lots`：按买入交易日保存批次，支持 T+1 可卖数量。
- `positions`：按账户和标的聚合的可重建持仓快照。
- `simulation_runs`：每次信号/行情执行的参数、结果、错误和汇总。
- `account_snapshots`：每日或每次运行后的现金、持仓市值、净值、收益和回撤。
- `risk_events`：风控通过、拒绝、警告和原因。
- `audit_events`：导入、订单状态变化、成交、结算、恢复和人工操作的不可变审计事件。

金额和价格不使用 SQLite 浮点：数据库使用定标整数（价格/金额统一 1e-4 元单位）或规范化文本，Python 侧统一使用 `Decimal`；所有 API 对外输出字符串金额，避免浮点误差。

提供：

- `db migrate`
- `db backup --output ...`
- `db restore --input ...`
- `db integrity-check`
- `rebuild-balances`：从资金账簿、成交和批次重建物化余额，发现漂移即报错。

### 资金流与结算模型

支持完整账户资金流：

1. `DEPOSIT`：入金增加可用现金和可提现现金。
2. `WITHDRAWAL`：只允许从可提现现金扣除，禁止透支。
3. 买入成交：扣除成交金额和买方费用，资金进入已结算账簿；账户现金、冻结现金和账簿同时更新。
4. 卖出成交：成交金额扣除卖方费用后进入可交易现金；按 A 股规则计入待结算金额，下一交易日释放为可提现现金。
5. 手续费、印花税、滑点均独立记账，可按账户配置查询。
6. 每笔资金变化带 `reference_type/reference_id/idempotency_key`，重复重试不会重复变动现金。

默认费用配置：

- 股票：双边佣金、最低佣金、卖出印花税；
- ETF：双边佣金、最低佣金、无股票印花税；
- 费率均可通过账户配置覆盖；系统在报告中明确展示费用假设，不伪装为真实券商费用。

### 信号导入与目标持仓再平衡

`SignalImporter`：

- 校验 `signal.v1`、时间有效性、策略 ID、来源、权重和标的格式。
- 保存原始 JSON 和规范化版本。
- 同一个 `signal_id` 重复导入返回已有记录，不重复创建订单。
- `RECORD_ONLY` 只入库并产生审计事件，不交易。
- 支持单文件、目录批量、JSON/ZIP 导入；ZIP 只接受白名单文件，拒绝路径穿越。

`RebalancePlanner`：

- 用信号生效时点的账户总权益和行情计算目标数量。
- 优先生成卖单，再生成买单；股票/ETF 默认最小交易单位 100，可配置。
- 目标权重不足整手时向下取整并保留现金，目标数量不能为负。
- 目标组合中消失的旧持仓生成清仓订单，但遵守 T+1 和可交易状态。
- 每个订单保留 `signal_id`、目标权重、计算权益、引用行情快照和规划原因。

### 模拟成交、风控和 T+1

`ExecutionSimulator`：

- 买入优先使用卖一，卖出优先使用买一；缺盘口时使用 last，并按方向加入滑点。
- 支持固定滑点、最大成交量参与率、部分成交、行情缺失、停牌、涨跌停和不可交易拒单。
- 订单状态：`CREATED → RISK_REJECTED/SUBMITTED → PARTIALLY_FILLED/FILLED/CANCELED/FAILED`。
- 每次状态变化写入审计事件；同一订单重复执行不会重复生成成交。

`RiskEngine` 默认包含：

- 最大单笔金额；
- 最大标的权重；
- 最大换手率；
- 最低现金保留；
- 最大订单数和最大参与率；
- 交易时间、停牌、涨跌停、数量整手；
- 信号过期和 `gate_status` 检查；
- 卖出可用数量和 T+1 检查。

`SettlementService`：

- 买入批次当天不可卖，下一交易日可卖；
- 同一交易日卖出所得可用于后续买入，但默认不可提现；
- 每个交易日执行待结算现金释放；
- 失败恢复时根据唯一结算键重放，不重复增加现金。

## 验证与验收

### 自动测试

- 协议 schema、权重总和、时间有效性、非法 JSON、ZIP 路径穿越。
- SQLite 迁移、外键、唯一幂等键、WAL、备份恢复和 `integrity_check`。
- 入金、出金、余额不足、交易资金、待结算资金和手续费的精确变化。
- 目标组合买卖、卖出优先、整手取整、现金保留和最大仓位。
- 买一/卖一、滑点、部分成交、停牌、涨跌停、行情缺失。
- T+1：当日买入拒绝卖出，下一交易日允许卖出。
- 重复导入、重复模拟、进程重启、余额重建不重复扣款/加款。
- HTTP API 和 CLI 的端到端流程。

### 端到端验收场景

1. 创建 100 万元账户并记录初始入金；数据库中可见入金流水。
2. 从 M-quant 导出一个 `TARGET_PORTFOLIO` 信号，在模拟盘导入；重复导入两次只生成一个信号记录。
3. 导入行情并执行；检查订单、成交、手续费、滑点、现金、持仓批次和审计事件。
4. 当日尝试卖出刚买入的标的，必须因 T+1 拒绝；推进到下一个交易日后允许卖出。
5. 资金不足、信号过期、策略 `RECORD_ONLY`、停牌和涨跌停均只产生风控事件，不改变账户资金。
6. 模拟卖出后，可交易现金增加但可提现现金在结算日前不增加；执行结算后可提现现金释放。
7. 重启服务并执行 `rebuild-balances`，重建结果与运行前一致。
8. 页面显示账户、持仓、订单、成交和资金流水，JSON/CSV 导出可供复核。
