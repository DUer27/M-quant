# 模拟盘升级实施计划

## 总体目标

把 `mquant-execution` 从“文件导入 + 历史回放终端”升级为：

1. **实时行情 PAPER 终端**：通过可替换行情源实时刷新最新价、买卖盘、成交量和行情时间，并保留来源、延迟和失败状态。
2. **M-quant 直连策略链路**：页面切换只是 UI 入口，模拟盘直接读取 M-quant 的策略目录/信号 API，不再要求手工导出再导入文件；文件导入继续保留作为离线/备份路径。
3. **多资金情景模拟**：支持不同初始资金、追加入金、出金、佣金、滑点、单票上限、现金保留、成交参与率、市场冲击等场景，并生成可比较的净值/成交/风控结果。
4. **结构化结果输出**：本次实现稳定的 `paper-report.v1` API/JSON 结果契约，为后续智能体读取做准备；本次不实现智能体接入。

## 第一阶段：实时行情层

### 新增模块

在 `mquant-execution/mquant_execution/` 新增：

- `market_sources.py`：行情源抽象与东方财富 HTTP 适配器。
- `market_service.py`：最新快照刷新、批量刷新、重试、超时、来源标记、时间戳和状态。
- `market_scheduler.py`：仅 PAPER 行情轮询；默认间隔可配置，支持启动/停止，不创建交易订单。

### 数据库

新增迁移 `migrations/003_live_market.sql`，建立：

- `live_quotes`：`symbol`、最新价、买一/卖一、开高低、昨收、成交量、成交额、涨跌、行情时间、抓取时间、source、latency、status、error。
- `market_sync_runs`：每次刷新批次、开始/结束、请求标的数、成功数、失败数、来源和错误摘要。
- 对 `market_bars` 增加必要索引，不破坏历史 bars。

实时行情接口：

- `GET /api/v1/market/live?symbols=...`
- `POST /api/v1/market/live/refresh`
- `GET /api/v1/market/sync-runs`
- `GET /api/v1/market/status`

行情页面显示：

- 最新价、涨跌、涨跌幅；
- 买一/卖一；
- 日内 OHLC；
- 成交量、成交额；
- 行情时间、刷新时间、数据源、延迟；
- 失败/过期/无数据状态；
- 手动刷新、自动刷新间隔和停止按钮。

行情源失败时必须明确显示 `STALE`/`SOURCE_ERROR`，不能静默使用旧价格模拟成交。历史 `market_bars` 继续用于 K 线和回放；实时 `live_quotes` 用于实时观察和 PAPER 最新估值。

## 第二阶段：M-quant 策略直连

### M-quant 侧新增只读接口

在 `platform/quant-factor-platform/server.mjs` 增加：

- `GET /strategy-api/execution-catalog`：返回可进入 PAPER 的策略、准入状态、策略 ID、版本、目标组合来源、最新信号日期、阻断原因。
- `GET /strategy-api/execution-signal?strategy=<id>`：返回结构化 `signal.v1`，服务端继续做确定性 ID、权重闭合和 `RECORD_ONLY` 判断。
- `GET /strategy-api/execution-health`：返回 M-quant API 版本和最新信号状态。

原有下载 JSON/CSV/ZIP 接口保留，用于离线导入和审计。

### 模拟盘侧连接器

新增：

- `mquant_client.py`：HTTP GET、超时、重试、响应 schema 校验、M-quant 可用性状态。
- `strategy_sync.py`：拉取策略目录、选择策略、拉取 signal.v1、保存原始 JSON 和同步事件。

新增接口：

- `GET /api/v1/strategy/catalog`
- `POST /api/v1/strategy/sync`
- `POST /api/v1/accounts/{id}/strategy/activate`
- `GET /api/v1/accounts/{id}/strategy/current`
- `POST /api/v1/accounts/{id}/strategy/run-once`

模拟盘页面新增“策略连接”区：

- M-quant 地址配置，默认 `http://127.0.0.1:5555`；
- 连接状态和最后同步时间；
- 可执行策略列表；
- `RECORD_ONLY` 原因；
- “同步策略”“激活策略”“运行一次 PAPER”按钮；
- 当前策略、signal_id、目标持仓数和准入状态。

策略状态规则：

- 只有 `TARGET_PORTFOLIO` 且 `gate_status` 在受控 PAPER 白名单内，才允许 run-once；
- `RECORD_ONLY` 只同步和审计；
- 策略接口不可用时不得使用旧信号自动交易，必须显示 `MQUANT_OFFLINE`；
- 每次同步原始信号、策略版本、signal_id、source_url、同步时间和校验结果。

## 第三阶段：多资金情景和资金流

### 场景模型

新增 `scenarios`、`scenario_cashflows`、`scenario_runs` 表：

- 每个场景独立账户资金和配置；
- 场景可以复制基准账户或从零创建；
- 不改变正式 `paper` 账户；
- 场景运行结果可删除、重跑和比较。

配置包括：

- 初始资金；
- 入金/出金计划；
- 佣金率和最低佣金；
- 股票印花税、ETF 印花税；
- 固定滑点；
- 最大单笔金额；
- 最大单票权重；
- 最低现金保留；
- 最大换手；
- 成交量参与率；
- 冲击成本模型；
- 最大订单数。

### API/CLI

- `POST /api/v1/accounts/{id}/scenarios`
- `GET /api/v1/accounts/{id}/scenarios`
- `POST /api/v1/scenarios/{id}/cashflows`
- `POST /api/v1/scenarios/{id}/run`
- `GET /api/v1/scenarios/{id}/report`
- `GET /api/v1/scenarios/compare?ids=...`

CLI：

```bash
python -m mquant_execution scenario create --account paper --name 100万基准 --cash 1000000
python -m mquant_execution scenario cashflow --scenario <id> --date 2026-01-02 --type DEPOSIT --amount 500000
python -m mquant_execution scenario run --scenario <id> --start 2025-01-02 --end 2026-07-22
python -m mquant_execution scenario compare --ids <id1>,<id2>
```

页面新增“资金情景”区域，展示：

- 场景资金流时间线；
- 总资产、净值、累计盈亏、收益率、最大回撤；
- 现金/持仓/待结算变化；
- 成交率、手续费、滑点成本、换手率；
- 场景之间对比曲线和差异。

## 第五阶段：验证和安全边界

### 自动化测试

- 东方财富响应解析、字段映射、超时、重试、source error/stale。
- 实时刷新写入 `live_quotes`，重复刷新幂等。
- M-quant execution catalog/signal 拉取、离线、超时、schema 错误、RECORD_ONLY 阻断。
- 直连同步后 signal_id 和原始 JSON 进入审计，重复同步不重复订单。
- 资金情景入金、出金、手续费、滑点、参与率、冲击成本和多场景隔离。
- paper-report.v1 字段完整性和金额/盈亏基准。
- 现有所有测试继续通过。

### 手工端到端验收

1. 打开模拟盘，点击实时刷新，看到 `LIVE`、行情时间、买一卖一和数据源；断网后显示 `SOURCE_ERROR` 或 `STALE`，不假装实时。
2. 模拟盘直接加载 M-quant 策略目录，选择 `akshare_regime_switch_contraction_mean_reversion_v1`，同步 signal，显示 `TARGET_PORTFOLIO` 和 15 个目标标的。
3. 点击 `run-once PAPER`，生成订单/成交或可解释拒单；刷新页面看到资金、持仓、成交、K 线标记。
4. 创建 100 万、300 万、1000 万三个情景，同一策略/行情分别运行，比较成交率、冲击、费用、回撤和最终净值。
5. 重新运行相同场景，不能重复扣现金或重复创建成交。
6. 读取 `paper-report.v1`，确认可完整表达行情来源、策略状态、资金、持仓、订单、成交、风险和限制。

## 本次不实现但预留方案

- 研究智能体只读取 `paper-report.v1`、`market/status`、`strategy/current` 和证据接口；不直接访问数据库。
- 后续增加 `agent_context.v1`，把报告、策略证据、行情状态和数据限制组合成只读上下文。
- 智能体动作必须是建议或需要用户确认的 PAPER 操作，不允许自动升级准入或 LIVE 下单。
